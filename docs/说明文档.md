## 验证用例（建议按顺序问）

1. **正常调用**："帮我查下用户 zhangsan" → 模型调 `query_user`，返回结果后自然语言总结。
2. **校验失败自动重试**："查用户"（故意不给 keyword）→ 工具返回 `参数校验失败：keyword 不能为空` → 模型下一轮会追问或补参数。
3. **枚举约束**："用 calculator 算 2 的 3 次方" → 模型可能给 `op=power`，被 `@Pattern` 拦下后它会自己改成 mul 连乘。
4. **业务校验**："查 root 用户" → `execute()` 抛 `不允许查询 root 账号`，这个错误同样会喂回模型。

## 后续接企业系统的扩展点

- **新工具**：写个 `@Component implements Tool`，Spring 自动注册，不用改循环。
- **工具读真实数据源**：在 `execute()` 里注入 `Mapper` / RPC client 即可。
- **多轮会话**：现在 history 是单次请求内的，要持久化就把 `List<ChatMessage>` 按 sessionId 存 Redis。
- **流式**：`OllamaRequest.stream` 改成 true，用 `BodyHandlers.ofLines()` 逐行解析即可。

一个提醒：Spring Boot 3.0.2 自带的 hibernate-validator 是 8.0.x，对 record 组件约束的支持是好的；如果你后面升到 Boot 3.2+，会自动换到 hibernate-validator 9.x，代码不用动。

## 切企业 MySQL

1. 先在 MySQL 里执行 `doc/schema-mysql.sql` 建库建表。
2. 打开 `application.properties` 里注释好的 MySQL 段，把 H2 段注释掉，密码改成你的。
3. `spring.sql.init.mode=never`（表已手动建）。
4. 代码一行不用动。

一个小提醒：H2 用了 `MODE=MySQL` 兼容 `CONCAT` 和 `LIMIT/OFFSET`，所以 Mapper 里的 SQL 在两边都能跑。
